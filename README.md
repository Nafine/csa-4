## Язык программирования

---

### Форма Бэкуса-Наура

```ebnf
program ::= top_level*

top_level ::= func_decl | var_decl

func_decl ::= "def" ID "(" params? ")" type block

params ::= param ("," param)*
param ::= ID type

block ::= "{" stmt* "}"

stmt ::= var_decl 
    | assign_stmt
    | expr_stmt
    | branch_stmt
    | while_stmt
    | return_stmt

var_decl ::= "var" ID type ("=" expr)? ";"
    | ID ":=" expr ";"

assign_stmt ::= ID "=" expr ";"

branch_stmt ::= "if" "(" expr ")" block 
                ("else" "if" "(" expr ")" block)*
                ("else" block)?

while_stmt ::= "while" "(" expr ")" block

return_stmt ::= "return" expr? ";"
expr_stmt ::= expr ";"

expr ::= expr "||" expr 
    | expr "&&" expr
    | expr ("==" | "!=") expr
    | expr ("<" | ">" | "<=" | ">=") expr 
    | expr ("+" | "-") expr
    | expr ("*" | "/" | "%") expr
    | unary_expr
    | primary_expr

unary_expr ::= "!" expr 
    | "-" expr
    | "++" ID
    | "--" ID

primary_expr ::= ID
    | INT_LIT
    | BOOL_LIT
    | STRING_LIT
    | "(" expr ")"
    | func_call
                 
func_call ::= ID "(" args? ")"
    | "print" "(" expr ")"
    | "read" "(" ")"

args ::= expr ("," expr)*

type ::= "int" | "bool" | "string" | "void"

INT_LIT ::= [0-9]+
BOOL_LIT ::= "true" | "false"
STRING_LIT ::= \"[^"]*\"
ID ::= [a-zA-Z_][a-zA-Z0-9_]*
```

### Семантика

- Стратегия вычислений -- аппликативная (applicative order)
- Области видимости -- лексические (lexical scoping)
    - Глобальные переменные - объявленные вне тела функций - доступны в любом месте программы
    - Локальные переменные - объявленные внутри функции - доступны только внутри этой функции
    - Затенение (shadowing) - локальная переменная может затенять глобальную переменную с тем же именем
- Типизация -- статическая, явная. Типы: `int`, `bool`, `string`, `void`
- Литералы -- целые числа (67), булевы значения (true, false), строки ("hello")
- Комментарии -- однострочные (// comment)
- Точки входа -- функция `main` без параметров и возвращаемым значением `void`
- Строки -- null-terminated (C string)
- Ввод-вывод -- через встроенные функции `print` и `read`

## Организация памяти

---

Архитектура - фон-Неймановская: код и данные расположены в едином линейном адресном пространстве.

Программист имеет прямой доступ только к аккумулятору и (косвенно через `PUSH/POP/CALL/RET`) к стеку. Прочие
регистры (`PC`, `SP`, `AR`, `CR`, `DR`, `Z`, `N`) служебные и обновляются микрокодом.

- Машинное слово - 32 бита (знаковое представление в two's complement).
- Поле операнда инструкции - 24 бита со знаковым расширением; этого достаточно для адресации всей памяти.
- Размер физически моделируемой памяти данных - `2^24 = 16777216` слов (`DataPath.MEM_SIZE`). Старшие два адреса
  (`0xFFFFFFFE`, `0xFFFFFFFF`) отображены на устройства ввода-вывода.

```
                       Registers
  +----------------------------------------------+
  | AC  - аккумулятор (программно видимый)       |
  | SP  - указатель стека                        |
  | PC  - счётчик инструкций                     |
  | AR  - адресный регистр                       |
  | CR  - регистр инструкции (opcode | operand)  |
  | DR  - буфер обмена с памятью                 |
  | N,Z - флаги, выставляются при flag_l         |
  +----------------------------------------------+

                       Memory
  +--------------------------------------------------+
  | 0x000000  | jmp main                             |
  |  ...      | тела функций (RET в конце каждой)    |
  |  ...      | тело main (HALT в конце)             |
  |-----------+--------------------------------------|
  | data_base | литералы (>24 бит), строки           |
  |  ...      | глобальные переменные                |
  |  ...      | параметры функций (`fn.param`)       |
  |  ...      | локальные переменные (`scope_N.var`) |
  |  ...      | служебные слоты ($tmp, $print_ptr…)  |
  |-----------+--------------------------------------|
  |  ...      | свободная память                     |
  |-----------+--------------------------------------|
  | 0xFFFFFD  | начальное значение SP                |
  | 0xFFFFFE  | INPUT_ADDR  (memory-mapped ввод)     |
  | 0xFFFFFF  | OUTPUT_ADDR (memory-mapped вывод)    |
  +--------------------------------------------------+
```

### Отображение программы и данных

Транслятор укладывает инструкции в начале памяти, сразу после них следует секция данных. Адреса символов
доразрешаются после генерации.

#### Литералы

- Значения `0 ≤ N < 2^24` уезжают в операнд через immediate-формы инструкций (`LDI`, `ADDI`, `SUBI`,
  `MULI`, `DIVI`, `REMI`, `CMPI`). Значения, не помещающиеся в 24 бита, помещаются в статическую память и
  загружаются обычным `LD addr`.
- Булевы литералы транслируются в `LDI 0` или `LDI 1`.
- Строковые литералы размещаются в статической. В инструкцию идёт адрес начала строки через `LDI`.

#### Строки (cstr)

Строки лежат посимвольно: каждый символ - отдельное 32-битное слово, в конце добавляется `0` как
терминатор. Адрес строки - это адрес её первого символа.

#### Глобальные переменные

Размещаются в статической памяти. Если объявление содержит инициализатор
(`var x int = 42;`), значение попадает прямо в слово при выделении. В противном случае слово
инициализируется нулём, а вычисление инициализатора выполняется в начале `main`.

#### Локальные переменные

Каждая переменная получает индивидуальное слово в статической памяти, а имя квалифицируется текущей цепочкой scope-ов:
`scope_0.x`, `scope_3.tmp`. Поиск имени идёт от ближайшего scope
к глобальному.

#### Параметры функций

Каждый параметр получает выделенное слово под именем `fn_name.param_name`. На месте вызова транслятор
сначала вычисляет аргументы и складывает их в эти слоты (`ST fn.p`), затем выполняет `CALL fn`.

#### Стек

Растёт вниз от `0xFFFFFD`. Используется только для:

- временных значений во время вычисления выражений (`PUSH`/`POP`),
- адреса возврата из функций (`CALL` пишет `PC`, `RET` забирает обратно).

#### Инструкции

Лежат с адреса `0x000000`. Самой первой инструкцией всегда стоит `JMP main` - затем компонуются тела
функций, и в конце - тело `main`, заканчивающееся `HALT`.

## Система команд

---

### Особенности процессора

- Архитектура: аккумуляторная (acc) -- все операции с данными проходят через регистр ACC.
- Ввод-вывод:
    - memory-mapped (mem) -- порты ввода/вывода отображены в адресное пространство, взаимодействие напрямую через
      память (LOAD, STORE).
    - ввод-вывод осуществляется как поток токенов, при старте модели есть буфер,
      в котором представлены все данные ввода (['h', 'e', 'l', 'l', 'o']). Если данные в буфере кончились --
      моделирование останавливается.
- Поток управления: инкремент PC после каждой инструкции; условные/безусловные переходы; вызов/возврат из функций через
  стек.

### Команды

Типы данных в модуле Opcode, Instruction.

| Команда  | Опкод | Такты | Описание                                  |
|:---------|:------|-------|:------------------------------------------|
| **LD**   | 0x01  | 3     | AC <- Mem[arg]                            |
| **LDR**  | 0x02  | 5     | AC <- Mem[Mem[arg]]                       |
| **LDI**  | 0x03  | 1     | AC <- arg                                 |
| **ST**   | 0x04  | 3     | Mem[arg] <- AC                            |
| **STR**  | 0x05  | 4     | Mem[Mem[arg]] <- AC                       |
| **ADD**  | 0x10  | 3     | AC <- AC + Mem[arg]                       |
| **ADDI** | 0x11  | 1     | AC <- AC + arg                            |
| **SUB**  | 0x12  | 3     | AC <- AC - Mem[arg]                       |
| **SUBI** | 0x13  | 1     | AC <- AC - arg                            |
| **MUL**  | 0x14  | 3     | AC <- AC * Mem[arg]                       |
| **MULI** | 0x15  | 1     | AC <- AC * arg                            |
| **DIV**  | 0x16  | 3     | AC <- AC / Mem[arg]                       |
| **DIVI** | 0x17  | 1     | AC <- AC / arg                            |
| **REM**  | 0x18  | 3     | AC <- AC % Mem[arg]                       |
| **REMI** | 0x19  | 1     | AC <- AC % arg                            |
| **CMP**  | 0x20  | 3     | Set NZ from AC - Mem[arg]                 |
| **CMPI** | 0x21  | 1     | Set NZ from AC - arg                      |
| **NOT**  | 0x22  | 1     | AC <- ~AC                                 |
| **NEG**  | 0x23  | 2     | AC <- -AC (через ~AC + 1)                 |
| **JMP**  | 0x30  | 1     | PC <- arg                                 |
| **BEQ**  | 0x31  | 2     | PC <- arg if Z = 1 else PC + 1            |
| **BNE**  | 0x32  | 2     | PC <- arg if Z = 0 else PC + 1            |
| **BGE**  | 0x33  | 2     | PC <- arg if N = 0 else PC + 1            |
| **BGT**  | 0x34  | 3     | PC <- arg if N = 0 && Z = 0 else PC + 1   |

| **PUSH** | 0x40  | 3     | MEM[SP] <- AC; SP--                       |
| **POP**  | 0x41  | 4     | SP++; AC <- Mem[SP]                       |
| **CALL** | 0x50  | 3     | PUSH(PC); PC <- arg                       |
| **RET**  | 0x51  | 4     | PC <- Mem[++SP]                           |
| **HALT** | 0xFF  | 1     | 💀                                        |

## Транслятор

### Интерфейс командной строки

```
uv run python cli.py compile <input.tw> <output.bin>
uv run python cli.py run     <output.bin> [<input.txt> [<trace.log>]]
```

Команда `compile` рядом с `<output.bin>` создаёт `<output.bin>.txt` - отладочный листинг вида
`<address> - <HEXCODE> - <mnemonic>`.

Команда `run` без `<input.txt>` запускает программу с пустым потоком ввода; без `<trace.log>` -
не пишет журнал состояний (быстрее, актуально для prob1 на десятки миллионов тактов).

### Этапы

```
src -> tokenize -> parse -> analyze -> codegen -> (instructions, data) -> write_file
```

- **`tokenize`** (`translator/tokenizer.py`) - лексер на регулярных выражениях.
  Токены: `INT_LIT`, `BOOL_LIT`, `STRING_LIT`, `KEYWORD`, `ID`, `OP`, `PUNCT`. Комментарии и
  пробелы отбрасываются здесь же.
- **`parse`** (`translator/parser.py`) - рекурсивный спуск, строит дерево из узлов.
  AST - человекочитаемый, печатается в `out_ast` golden-тестов.
- **`analyze`** - статический анализ.
  Проверяется:
    - наличие и сигнатура `main(): void`
    - уникальность имён функций
    - типизация выражений
    - условия в `if` / `else if` / `while` - `int` или `bool`
    - все пути в функции с возвратным типом завершаются `return`
    - инициализатор глобала - только литерал
    - массивы (`int[N]`/`bool[N]`) не могут быть параметрами и не имеют инициализатора
    - индексирование массивов: индекс `int`, тип значения совпадает с типом элемента
- **`codegen`** - обход AST и генерация инструкций с распределением памяти:
    - **scope stack** формирует скоупы `scope_N.var` для локальных переменных
    - Инструкция создается с пустым операндом и сохранением пары (индекс, имя) в специальную
      мапу. После первого прохода подставляются вычисленные адреса (для данных - со смещением относительно инструкций).
    - **сравнения** через `CMP` + условный переход в материализацию `0`/`1` в ACC.

### Структура бинарного файла

- Сначала инструкции, по 4 байта каждая, в формате `Opcode (8 bits) | Operand (24 bits)`.
- Затем секция данных, по 4 байта на слово.

Дополнительно `cli.py compile` пишет рядом текстовый дизассемблерный листинг `<output.bin>.txt`.

### Data Path

Регистры реализованы как защёлки, замыкаемые отдельными управляющими сигналами:

- **Защёлки регистров**: `flag_l`, `acc_l`, `dr_l`, `sp_l`, `pc_l`, `cr_l`, `ar_l` - замкнуть
  соответствующий регистр на текущем такте.
- **Мультиплексоры входов**:
    - `ar_sel in {PC, CR.arg, SP, DR}` - источник для `AR`;
    - `alu_left in {0, ACC, SP}`, `alu_right in {0, CR.arg, PC, DR}` - операнды ALU.
- **ALU** реализует `ADD, SUB, MUL, DIV, REM, INC, DEC, NOT`.
  По результату операции выставляются флаги `Z` (нулевой результат) и `N` (старший бит результата),
  если активен `flag_l`.
- **Доступ к памяти**:
    - чтение: при `dr_l = 1` в `DR` загружается `data_mem[AR]`. Если `AR == INPUT_ADDR`,
      вместо чтения памяти из входного буфера достаётся очередной токен; пустой буфер ведёт к
      исключению, что останавливает моделирование.
    - запись: при `mem_w = 1` в `data_mem[AR]` пишется значение, выбранное `mem_src` (`ACC` или `PC`).
      Если `AR == OUTPUT_ADDR`, значение вместо памяти попадает в выходной буфер.

### Control Unit

- **Декодер опкода**: таблица `DECODER[256]`, отображающая `CR.opcode` в адрес первой микрокоманды
  обработчика. Срабатывает в третьем такте `FETCH` под условием `cond = DECODE`.
- **Память микрокоманд** `MROM[128]` - реализует все инструкции через последовательности
  одиночных микрокоманд.
- **Модуль выбора адреса следующей микрокоманды**:
    - `cond = NONE`   -> `mpc <- (mpc + 1) mod 128`;
    - `cond = ALWAYS` -> `mpc <- next_addr`;
    - `cond = EQ/NE/GE/LT` -> проверка флагов `Z`/`N`, переход на `next_addr` или инкремент;
    - `cond = DECODE` -> `mpc <- DECODER[CR.opcode]`. Декод - за 1 такт. В третьем такте FETCH одновременно
      защёлкиваются регистр инструкции CR <- DR и счётчик микрокоманд
      mpc <- DECODER[CR.opcode]. DECODER - комбинационная схема.

Реализация условных команд (`BEQ`, `BNE`, `BGE`, `BGT`, `BLE`, `BLT`) - это именно конструкции из
2–3 микрокоманд: по флагам выбирается либо ветка тела `JMP`, либо возврат на `FETCH`.

### I/O

#### MMIO

Порты ввода-вывода отображены в адресное пространство, взаимодействие напрямую через память и стандартные команды
(LOAD, STORE).

#### STREAM

Ввод-вывод осуществляется как поток токенов, при старте модели есть буфер,
в котором представлены все данные ввода (['h', 'e', 'l', 'l', 'o']). Если данные в буфере кончились --
моделирование останавливается.

### Микрокоманды

Микрокоманда - 28 бит управляющих сигналов + адрес следующей микрокоманды.

| Биты  | Сигнал      | Описание                                                                 |
|-------|-------------|--------------------------------------------------------------------------|
| 27    | `halted`    | 1 = остановка симуляции                                                  |
| 26    | `flag_l`    | 1 = защёлкнуть `N`, `Z` от результата ALU                                |
| 25    | `acc_l`     | 1 = защёлкнуть `ACC`                                                     |
| 24    | `dr_l`      | 1 = прочитать `data_mem[AR]` (или порт ввода) в `DR`                     |
| 23    | `sp_l`      | 1 = защёлкнуть `SP`                                                      |
| 22    | `pc_l`      | 1 = защёлкнуть `PC`                                                      |
| 21    | `cr_l`      | 1 = защёлкнуть `CR`                                                      |
| 20    | `ar_l`      | 1 = защёлкнуть `AR` от выбранного источника                              |
| 19    | `mem_src`   | источник записи в память: `0 = ACC`, `1 = PC`                            |
| 18    | `mem_w`     | 1 = записать выбранный источник в `data_mem[AR]`                         |
| 17-16 | `ar_sel`    | `00 = PC`, `01 = CR.arg`, `10 = SP`, `11 = DR`                           |
| 15-14 | `alu_left`  | `00 = 0`, `01 = ACC`, `10 = SP`                                          |
| 13-12 | `alu_right` | `00 = 0`, `01 = CR.arg`, `10 = PC`, `11 = DR`                            |
| 11-9  | `alu`       | `000 ADD, 001 SUB, 010 MUL, 011 DIV, 100 REM, 101 INC, 110 DEC, 111 NOT` |
| 8-6   | `cond`      | `000 NONE, 001 ALWAYS, 010 EQ, 011 GE, 100 NE, 101 LT, 111 DECODE`       |
| 5-0   | `next_addr` | адрес следующей микрокоманды (если активирован условием)                 |

Цикл `FETCH` занимает 3 такта: `AR <- PC`; `DR <- Mem[AR]`, `PC <- PC + 1`;
`CR <- DR`, `mpc <- DECODER[DR]`. Дальше выполняется обработчик инструкции и в финальной
микрокоманде каждой инструкции стоит `cond = ALWAYS, next_addr = 0` - возврат к началу `FETCH`.

- `hello.yaml` - `print("hello world\n")`.
- `cat.yaml` - потенциально бесконечный echo стрима ввода до EOF.

- `sort.yaml` - пузырьковая сортировка списка чисел из ввода.
- `double_precision.yaml` - арифметика 64-битных чисел на 32-битных словах.

### Пример прогона инструментальной цепочки

Допустим, есть исходник `hello.tw`:

```text
def main() void {
    print("hello world\n");
}
```

Компиляция и запуск:

```bash
$ uv run python cli.py compile hello.tw hello.bin
$ cat hello.bin.txt | head
0000 - 30000001 - JMP 0x01
0001 - 0300000b - LDI 0x0b
0002 - 04000018 - ST 0x18
...

$ printf "" > empty.in
$ uv run python cli.py run hello.bin empty.in hello.trace
Time in ms: 3
hello world
```

Фрагмент `hello.trace`:

```text
Tick: [1] mPC=01 CR=00000000 ACC=          0 PC=00000001 SP=00fffffd AR=00000000 DR=30000001 Z=0 N=0
Tick: [2] mPC=45 CR=30000001 ACC=          0 PC=00000001 SP=00fffffd AR=00000000 DR=30000001 Z=0 N=0
```

Поля: `Tick` - счётчик тактов; `mPC` - адрес микрокоманды в `MROM`; `CR` - текущая инструкция
(`opcode | operand`); `ACC`, `DR`, `PC`, `SP`, `AR` - регистры; `Z`, `N` - флаги.
